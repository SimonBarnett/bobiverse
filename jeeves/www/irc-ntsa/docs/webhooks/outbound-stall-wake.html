Jeeves stall / ticket-closure wake (outbound) POST https://<operator-configured-wake-host>/ (JEEVES_TICKET_CLOSURE_WAKE_URL)

Direction: out · Purpose: HTTPS wake callbacks when MONITORING detects stalls or ticket-closure events (same transport as FR #6391).

Who calls it: jeeves/tools/monitor/ticket_closure.py and common/scripts/stall_callbacks.py on the chair.

Auth (named only): Named only: whatever the wake URL operator configured (Bearer or shared header). Never documented as a literal secret here.

Request schema: JSON wake brief (event, subject, summary). No passwords.

Response schema: 2xx accepted; non-2xx retried with backoff.

Status codes: 2xx ok; connection errors queued/debounced.

Retry / idempotency: Debounced per event/subject; drain_pending retries.

Rate limits: Internal backoff (WAKE_BACKOFF_S .. WAKE_BACKOFF_MAX_S).

Reachability: Outbound from chair only. Not an inbound bob.ntsa.uk route.

Source: common/scripts/stall_callbacks.py, jeeves/tools/monitor/ticket_closure.py · Related: FR #6391 / #6439
