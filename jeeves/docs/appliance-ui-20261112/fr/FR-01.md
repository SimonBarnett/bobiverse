# FR-01 One Windows account field

## Goal

The login page accepts DOMAIN\user or user@domain in one box.

## Deliverables

- Login HTML has one account text input and a password input. It has no domain input.
- authenticate_windows_logon splits user@domain into sam and domain, and still splits DOMAIN\user.
- POST /api/login still accepts a JSON domain from older clients.
- CredMan is tried with the typed string and, when split, with the sam account name.
- The error text never includes the password.

## Testable

- Rendered login HTML contains one account field and does not contain name="domain".
- A fake LogonUser receives domain NTSA and user simon for both NTSA\simon and simon@ntsa.
- A failed Windows logon still calls CredMan.
