## Rules (all enforced in code and tests)

* **WinPS 5.1 PSModulePath (FR #7315 / FR #7355):** `powershell.exe` children (pytest, `read_fuel`, seat `prepare_seat_child_env`) use `C:\Windows\System32\WindowsPowerShell\v1.0\Modules` only so pwsh 7 `PSModulePath` cannot hide `Get-FileHash`. `PSModuleAutoLoadingPreference` is set to `All` (never inherit string `None` from the shop seat).
* **Tray**: compiled `bob-tray.exe` (`BobTray.cs`) owns the icon. **Agents** is a submenu (Automatic, Grok, Cursor, OpenCode). **Plan** is one click. Automatic and Plan omit `--agent`. Grok, Cursor, and OpenCode pass `--agent` and refuse instead of starting a different agent. Each start runs `bob-worker.exe --mode agent|plan --install-root <root> --machine-id <id>` (a per-user run copy under `%LOCALAPPDATA%\Bobiverse\worker\bin`, so the installed exe is never locked by a seat). Rebuild the tray with `scripts\Build-BobDialogs.ps1` and the worker with `scripts\Build-BobWorker.ps1`. Keep `scripts\opencode_fuel.py` on the install.
* **ALWAYS a NEW agent** (t765u): new session id every time; `--resume/--continue/-r/-c/--session/--chat` are refused (`assert_fresh`); a click never attaches to an existing agent/window/process.
* **ONE window** (t771u): the exe's visible console IS the agent's window. The agent inherits that console (no `CREATE_NEW_CONSOLE`), IRC relay / `!bored` / health run as threads of the same exe. Ending the exe ends the agent (close handler + kill-on-close job object);
  the agent exiting ends the exe. The Grok key prompt (no tokens left) is inside the same console, input hidden.
* **Seat diagnostics (FR #7917):** `%LOCALAPPDATA%\Bobiverse\worker\logs\seat-<nick>.log` records the initial/injected prompts, native session events/transcripts (including model/tool records), changed console snapshots, and captured CLI output. Each file is capped at 1 MiB with two rolling backups; records are redacted before truncation or persistence. Oversized native records are omitted. Grok keeps **inherited console stdin, stdout and stderr**: its own seat-local logs and console snapshots supply diagnostics, never stderr redirection. Startup records include the console host PID/image, window/buffer dimensions, input/output code pages, `TERM`, console modes and VT flags (null when unavailable). On exit or a watchdog recycle, `run_dir/last-exit.json` and the session log record the reason, exit code (null while still running), and last 32 lines (up to 8 KiB). Abnormal exits/stalls use automatic deduplicated exception intake; digest seat `last_exit` retains this evidence across idle/restart updates. Normal zero exits are recorded without filing a crash. A no-ack-after-assign recycle of a still-running agent is a normal recycle, not an abnormal exit or stall, and files no intake (FR #7978). Read these files without the TUI; validation on flamingo requires deploying the rebuilt worker and observing its next incident.
* **OpenCode fuel text (FR #8151 / #8207):** tool/PR/gh echo of `Free usage limit` / `subscribe to OpenCode Go` is not fuel. Only seat app-log `level=ERROR` or `AI_*` provider JSON arms a free-usage pause/GIVEUP; paid/go seats never emit `fuel-exhausted:opencode-free`. Bare `Retry-After` / HTTP 429 still pause via rate-limit path.
* **OpenCode fleet smoke (FR #6160):** `bob/scripts/Assert-BobOpencodeFleetSmoke.ps1` (PATH, auth presence/ACL never body, optional pong, `bob-worker --dry-run` `opencode_cmd`). Ops roll call: `bob/docs/opencode-fleet-enabled.md`.
* **OpenCode inject (FR #6158 / FR-OC-INJECT / FR #8270 / FR #8560):** when `BOB_WORKER_INJECT_PASTE` is unset, OpenCode seats default to batched KEY_EVENT (same as Cursor FR #4464). **Never** set `BOB_WORKER_INJECT_PASTE=1` for OpenCode on this fleet: clipboard paste / Ctrl+V leaves a stray `v` on the ReadLine path, `submit-verify` fails (`no turn receipt`), then GIVEUP loops. Launch recipes must use `BOB_WORKER_INJECT_PASTE=0` (keys). Worker hardening that ignores PASTE=1 for OpenCode is FR #8558 / PR #8561. Submit-verify turn receipt is `turn_started` or new bytes in `opencode-turns.jsonl`. OpenCode retries do not send Enter. A dead spawn fails fast (`probe=spawn kind=opencode`). The OpenCode GIVEUP wire is `submit-verify failed probe=no turn receipt kind=opencode`. Cursor and Grok stay bare `submit-verify failed` (VISION S3). Path logs include `kind=opencode`. The hard ceiling (default 1800000 ms) is time since the last output growth or worktree write, not wall-clock age, so a live turn is not killed while a child process merely exists (FR #7976 / #8008). CPU and descendants refresh the short idle watchdog only; they do not reset the hard-ceiling stall clock (FR #8008 / #8027). A kill reason names the last progress time. Repeated hard-ceiling GIVEUPs stamp `giveup_agent_kinds` so the same seat class (e.g. OpenCode) stops being re-offered that job.

* **Paid OpenCode / DeepSeek launch (FR #8560):** keep keys inject. Example env for a disk python seat:
  `BOB_OPENCODE_FORCE_PAID=1`, `BOB_OPENCODE_MODEL=opencode-go/deepseek-v4-pro`, `BOB_WORKER_INJECT_PASTE=0`,
  then `python bin/scripts/bob_worker.py --mode agent --agent opencode`. Do not relaunch with PASTE=1.
* **Progress heartbeat (FR #8155 / #8195 / #8249):** a dedicated `progress-heartbeat` daemon posts digest `last_progress` while an ACK is open and the seat wrapper process is alive. It does not share the health thread or block on turn / FINISH / retry callbacks that hold emitter `_cv` or the supervisor `RLock`. Cadence is `BOB_PROGRESS_HEARTBEAT_S` (default 120 s, clamp 30–900), keyed per ACK epoch. Skip reasons (`no-ack`, `fuel-hold`, `proc-exited`, `job-changed`, `stopping`) are rate-limited in `worker.log`. A heartbeat proves liveness for the stuck sweep, not useful progress.
* **Stale build (FR #2782 / #3180 / #7834):** `BOB_WORKER_STALE_BUILD_RECYCLE=0` turns detection off. When the install exe sha12 differs from the running copy (settled 60s), the seat still sends `!bored` and takes work. Digest `stale_build` carries `running`, `installed`, and `since`. One exception is filed per seat and build. The seat does not exit 8. Restart stays manual.
* **Failed agent turn (FR #7201 / #8247):** `turn_ended` with `status=error` (or an error field) while an ACK is open retries the last assign once, then `GIVEUP <TYPE> owner/repo#N failed-turn <class>: <first line>` (no secrets) so Jeeves can re-offer. Applies to Grok, Cursor, and OpenCode. Quiet successful turn-end with ACK still open remains the done-miss path. **OpenCode `external_directory` auto-reject (FR #8247):** classified as `external-directory`; the seat injects one corrective that names `<worktree>\.bob\tmp` (TEMP/TMP already point there). After `BOB_OPENCODE_EXTERNAL_DIR_LOOP_MAX` (default 2) rejection-ended turns it `GIVEUP … external-dir-loop`. Do not widen `%TEMP%` allow. Other error classes keep the FR #7201 assign-retry path.
* **OpenCode exe resolve (FR #7302):** `resolve_opencode_cmd` never crashes on WinError 448 (untrusted WinGet `Links\opencode.exe` reparse). It prefers `Programs\opencode\opencode.exe`, then Links when `is_file` is safe, then PATH. A 448 is a readiness miss (logged), not a worker abort.
* **Agent selection**: Automatic (no `--agent`) is Grok, then Cursor, then OpenCode (FR #3997 / #6120): local Grok weekly > 0 or unknown read -> `agent.exe`; else Cursor high or low pool > 0 -> `agent.cmd`; else OpenCode free or Go fuel > 0 -> `opencode.exe`; else a key prompt (memory only). `--agent grok|cursor|opencode` starts only that agent. A missing command, or OpenCode with no usable fuel, exits 4 and does not substitute. Readings: `tools/Get-BobAgentFuel.ps1` (it also passes OpenCode `windows` and `limiting`). When the local helper has no figure for the seat's own pool, a fresh fleet digest row (at most 10 minutes old, `fresh: true`) fills that pool only and is reused until it ages out (FR #8230). The worker never calls Go usage and never reads the Go key. A stale or missing fleet row stays unknown. ## UAT job flow (t820u, per repo since t853u)

UAT is per **repo**: Jeeves assigns `UAT owner/repo#0` once - and only when - every issue of the repo is closed (excluding needs-human, boards/mrb-home, harvest/skill records) and every PR is merged; never one UAT per PR. The seat should have implemented none of the cycle's merged PRs. The worker's `UAT` job (skill `bobiverse-bob-job-uat`, with its mermaid diagram) verifies the merged product against the **VISION** (`bob/VISION.md`, FR #1615; fleet umbrella remains `common/docs/vision.md`) and any specs, then branches on the gaps:
**gaps** -> one FR per gap filed through the intake (`Report-BobiverseIntakeIssue.ps1 -Kind fr`), verdict `UAT FAIL`, **no release**; **no gaps** -> documentation and READMEs updated (one docs PR), `VERSION` bumped, `Pack-BobiverseRelease.ps1`, `gh release create` using `common/scripts/uat_release.py` for title/tag (FR #7122: Priority Agent is `Priority Agent vX.Y.Z` / `vX.Y.Z`; `UAT PASS` and the date stay in notes), verdict `UAT PASS`.
The wire contract is unchanged: `ACK UAT owner/repo#0`, then `DONE UAT owner/repo#0 PASS|FAIL [url]` (or `NACK` / `GIVEUP`) in the worker's own `#<machine>`; Jeeves/the chair only does queue bookkeeping and never verifies, files or releases.

## Issues close with their PR (t826u)

* **FR**: the PR body carries `Closes <owner>/<repo>#N` (full form) for the originating issue; the worker checks `closingIssuesReferences` before `DONE FR`.
* **MRB**: PASS posts the board with head SHA and hands off (FR #3948): `gh pr merge --auto` or `merge-on-green pending` — seats never poll CI; Jeeves merges on green / re-queues on red or SHA change; held PRs never auto-merge. Otherwise it confirms the `Closes` link. If the issue is still open after the merge (non-default base branch, missing link) the worker closes it with a comment (PR url + verdict). `DONE MRB` only once the issue is closed or linked. **FR #791:** `gh issue close N --body-file` is an unknown flag â€” use `-c` / `--comment` (never `--body-file` on close; that flag is for `gh pr create` / `gh issue create`).
* **Duplicates (t857u)**: a worker that opens a PR searches the open issues/FRs for duplicates of what it fixes, comments `Duplicate of #N / fixed by PR #M`, closes them as not planned and lists them in the PR body (`Duplicates closed:`; real extra issues get their own `Closes <owner>/<repo>#D`). The MRB verifies the line and closes any it finds. Never `needs-human` / board issues.
* **Queue (chair)**: an `issues closed` webhook drops the issue's FR/PR rows (FR #180 point 4, also the hourly / gap GitHub resync — FR #3212); a merge queues no UAT row (UAT is per repo, see above). `gitclaim.extract_closes_issue_ids` understands `Closes #N` and `Closes owner/repo#N` (another repo's link is ignored).
