# bobiverse-airc-troubleshooting

> **CAST IRON RULE - HARVEST AND FILE EVERYTHING (read this first, every time).**
> 1. ALWAYS harvest skills you learn and file EVERY issue / FR / bug / gap you find to the intake webhook in the
>    SAME turn. Never leave a finding unfiled, never "note it for later", never skip it because it is small.
> 2. File with the intake webhook (no secret or login needed; `POST https://bob.ntsa.uk/bob/v1/intake`; offline it is
>    queued locally and retried):
>    `.\scripts\Report-BobiverseIntakeIssue.ps1 -Repo SimonBarnett/bobiverse -Kind issue -Title "short title" -Body "what / where / evidence / fix"`
>    (`-Kind issue|fr|skill|harvest`; always pass an explicit `-Repo owner/name`).
> 3. BEFORE finishing ANY debugging session run the harvest step:
>    `.\scripts\Invoke-BobiverseHarvest.ps1 -Summary "what broke / what fixed it" -Lesson "one learned playbook line"`
>    then `.\scripts\Invoke-BobiverseHarvest.ps1 -Flush` to resend anything that was queued while offline.
> 4. Never put a token, password, SASL/NickServ secret, key or private hostname in a filing, a skill or a log.

## FR #5003 (reverse DCC bulk for oversized shell replies)

| Large shell output floods IRC (minutes / reconnect wedge, see #5002) | Keep IRC as control plane. Caller may send `DCCLISTEN id=<job> host=<ip> port=<n> token=<hex>`; when output exceeds the bulk threshold and a matching offer exists, console **dials out** (NAT-friendly), streams body, waits for ACK sha256 (FR #5612), replies `DONE id=... exit=... bytes=N sha256=H via=dcc`. No ack or handshake failure falls back to existing IRC CONT paging (FR #4794). FR #5065: the fallback `err dcc failed` line uses the next unused seq before DONE (never seq=1 twice); else `ConvertFrom-AircRemoteReply` throws `duplicate seq=1`. Without `DCCLISTEN`, behaviour unchanged. Tip PR #5009 (`airc_dcc_bulk.py`). WP2 (#5008): TLS, ionos relay, bob-ear helper, live fleet timings. |

## FR #5008 (reverse-DCC TLS + framed leftovers)

| Windows reverse-DCC TLS handshake fails / digest mismatch on framed bulk | Pin TLS **1.2** (`ssl.PROTOCOL_TLSv1_2` / equivalent) --- TLS 1.3 `wrap_socket` can race the client close on Windows. Framed bulk must **slice the body to the declared length** and **keep recv leftovers** for the trailing digest (and relay ROLE leftover handling). Product tip: PR #5013; clean land without embedded key: PR #5017. |

## Harvest digest (lessons audit 2026-10-06)

## Large PRIVMSG bursts / flood disconnect (FR #4790)
| Truncated shell reply needs next page (FR #4794) | Send `CONT id=<job>` / `RESUME id=<job>` (optional `offset=N`) for the next `SHELL_REPLY_MAX_IRC_LINES` page; no re-run. Marker cites CONT. Large binaries: PUT/share (FR #4790). |
| Large sandbox file must not dump over Query PRIVMSG (FR #4795) | `GET path fetch=chunk` returns size/sha256/seqs only; pull each piece with `GETCHUNK id=<job> seq=N` (next GETCHUNK is the ack; console never pushes the next chunk). Plain GET stays head-only. Secret paths rejected. |

Symptom: console goes silent mid base64 dump; later STATUS gets no reply. Cause: Ergo fakelag / excess flood after hundreds of Query lines. Fix on tip: reply-line cap + truncate marker + token-bucket send pacing; reconnect on send failure. Controllers must not paste multi-KB base64 into shell stdout --- use PUT/file fetch.
