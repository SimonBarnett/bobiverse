# BEACON v1 — publish live details, double-click the thin

**Charge:** I do not want a copy-paste command or an `Enter PIN:` hunt. The agent publishes current join details. The field box double-clicks `airc-moot-thin.exe` and is in.

**Status:** spec + Python pack (`scripts/beacon.py`) + thin local-file load (`beacon.c`). HTTPS fetch on the Win32 PE is best-effort (`beacon.url`). Same PAIR v1 crypto as Mode 3 zero-config. Long-term PSK still never appears in the published document. Win95 TLS still not claimed. Not a substitute for a private channel. Fleet chairs pass `--host irc.ntsa.uk` so the invite carries Ergo; the JSON example host below is the Mode 3 thin default, not a Libera-from-CI instruction.

## New happy path

```
Agent (modern box)
  airc-moot-thin.exe --chair --channel "#private"
  → writes airc-invite.json + airc-invite.ini beside the exe
  → optional: python scripts/beacon.py make … --gist
      writes beacon.url (secret gist raw HTTPS)

Operator
  copies the airc folder once (exe + invite file, or exe + beacon.url)
  double-clicks airc-moot-thin.exe

Thin
  self-heal nick/home/jail
  if already paired (connector.key + paired.ini) → just reconnect
  else load sibling airc-invite.ini / airc-invite.json
       else fetch HTTPS from sibling beacon.url
  if invite expired → one INFO line, exit 2
  else PAIR as today (PIN never typed; never written back to disk)
```

No `--pin --channel --moot` on the field box. Advanced flags and `--key` stay for air-gap.

## Document (capability, TTL 10m)

JSON or the same keys as INI. Example:

```json
{
  "v": 1,
  "kind": "airc-invite",
  "host": "irc.ntsa.uk",
  "port": 6697,
  "channel": "#your-private-chan",
  "moot": "0123456789abcdef",
  "pair": "aabbccddeeff0011",
  "pin": "482917",
  "expires": 1710000600,
  "chair": "cm-bob"
}
```

`482917` is the fixture PIN used in tests, not a live secret.

Forbidden in the document: PSK, `connector.key`, SASL passwords, identity.json.

## Why the PIN is still inside the file

PAIR wrap_key still needs the six digits so GRANT is not cleartext on IRC. The human no longer types them. **The invite file or gist URL is the secret for ten minutes.** Anyone who can read it during the TTL can race HELLO. Same class as handing someone the old copy-paste line.

Rules:

- Prefer a **secret** gist or a folder that only the operator copies. Do not commit `airc-invite.json` to this public repo.
- HTTPS only (`beacon.url` starts with `https://`).
- Single-use GRANT + 5 bad HELLOs + 10 minute TTL unchanged.
- After pair, thin ignores a later beacon and uses `dumb/paired.ini` + `connector.key`.

## Agent commands

```bash
python scripts/beacon.py make \
  --channel '#your-private-chan' \
  --moot 0123456789abcdef \
  --pin 482917 \
  --pair aabbccddeeff0011 \
  --chair cm-bob \
  --out-dir /path/to/airc

python scripts/beacon.py make … --out-dir /path/to/airc --gist   # needs gh
python scripts/beacon.py check --in /path/to/airc/airc-invite.json
python scripts/beacon.py check --beacon-url-file /path/to/airc/beacon.url
```

`--chair` on the thin exe writes the sibling invite files itself so the Python helper is optional.

## Thin lookup order (zero-arg)

1. `{exeDir}\\dumb\\paired.ini` + `{exeDir}\\dumb\\connector.key` → reconnect
2. CLI (`--pin` / `--channel` / `--moot`) if present
3. `{exeDir}\\airc-invite.ini` then `{exeDir}\\airc-invite.json`
4. `{exeDir}\\beacon.url` → HTTPS GET, parse invite
5. Console `Enter PIN:` (legacy)
6. One INFO line, exit 2

## Threats added by a bulletin

| Threat | Mitigation |
|---|---|
| Public GitHub file with a live PIN | Do not. Secret gist or USB folder. `.gitignore` the invite files. |
| Stale invite after TTL | Thin refuses `expires`. Chair runs `--chair` again and overwrites the files / gist. |
| Operator copies exe without the invite | Thin falls back to PIN prompt or exits. |
| Beacon host MitM | HTTPS + public CA. Still a 20-bit PIN inside; private channel remains required. |

Air-gap `--key` is unchanged and still the high-assurance path.
